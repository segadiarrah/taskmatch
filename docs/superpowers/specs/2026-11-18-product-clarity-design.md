# TaskMatch: marketplace preserved, human execution added

The user corrects the previous delivery: TaskMatch remains a marketplace for AI agents and humans. Human Tasks is an added capability, not a replacement product. Public calls to action must explain concrete work and reach the correct existing workflow. Dashboards must make this addition visible, not merely add an obscure sidebar link. Prior autonomous implementation/deployment authorization remains applicable.

Current evidence: all public entry intents currently lead exclusively to /human-tasks. The homepage and company pages describe TaskMatch as only a human execution layer. Client/developer/admin landing pages remain the previous KPI screens. Existing permission contracts remain unchanged: client accounts create AI jobs; developer accounts register executors; Human Tasks supports all existing roles.

Chosen approach: restore the broader marketplace story in all five languages and preserve existing AI-job workflows. Public navigation exposes posting an AI project, human work and offering an AI agent, while a clearly identified Human Tasks section explains direct human requests and agent-to-human delegation. Preserve old human deep links using mission/work/agent intents; add explicit project/executor auth intents rather than silently redirecting existing URLs. Registration selects the correct existing role for the new executor intent, without account duplication or automatic role promotion. Existing accounts receive role-compatible destinations.

Backoffice: retain existing jobs/agents/tasks/payments views and add a prominent, localized action area to each dashboard, plus explicit human navigation destinations. Client sees AI project creation and human mission request; developer sees executor work plus agent authorizations and personal human work; admin sees AI operations alongside a Human Tasks panel with actual counts and review links. A small admin-only read endpoint aggregates human mission/profile counts without mutations or financial totals. Do not fabricate activity or counts. New features remain discoverable even when the platform has no human activity.

Design: reuse existing restrained paper surfaces, purple accent, typography and responsive layout. Give action links a concrete verb and an explanatory sentence. Avoid an unrelated theme change. Keep five-language coverage and provider-neutral public payment wording. Backend counts require admin authorization, no migration and no sensitive profile data. Preserve errors distinctly from zero counts.

Validation: route/role regression tests, five-language UI tests, mobile overflow and actual CTA navigation, admin count authorization and accuracy, full existing browser suite and frontend check/build. Production deployment uses backup, parallel candidate and verified Nginx reload; no live payment or fictitious production activity. Verify delivered public and authenticated surfaces, capture screenshots and report concrete before/after changes.
