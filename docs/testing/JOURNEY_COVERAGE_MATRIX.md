# TaskMatch journey coverage matrix

Inventory reviewed on **2026-11-18**, initially against revision `f792314` in the isolated journey worktree. This is a map of executable assertions and their fidelity, not a claim that every listed test has passed. Current full-suite and production traversal results belong in [the dated verification report](ALL_JOURNEYS_2026-11-18.md). That report may be produced after this inventory.

## What each type of evidence proves

| Label | Execution boundary | What it proves and what remains outside it |
| --- | --- | --- |
| Static/unit | Source, schemas or a service with controlled dependencies | Contract, calculations and failure handling. Does not prove a browser can finish a journey. |
| Browser fixture | Chromium with `page.route(...).fulfill(...)` or equivalent API fixtures | Rendering, navigation, localized copy, form/request shape and controlled recovery. Database persistence and authorization require separate evidence. |
| HTTP/DB | `httpx.ASGITransport(app=app)` and isolated PostgreSQL | Real FastAPI routing, authentication/dependency checks, domain services, transactions, concurrency and persisted projections. HTTP is in process; this bypasses reverse proxy, TCP deployment and browser integration. |
| Browser/API/DB | Chromium forwards API requests to the explicitly provisioned loopback API | Browser and running API integration with disposable accounts and persistent state. Provider boundaries and seeded prerequisites must be stated separately. |
| Production read | Read-only traversal of deployed pages and API GETs | Deployed availability, rendering and existing data projections. Cannot prove creation, charging, editing, review or deletion on production. |
| Provider fixture | Mocked Stripe/provider transport, disabled LLM or a deterministic local adapter | Server behavior at a controlled provider boundary. Does not prove external hosted payment, bank settlement, provider availability, generated-content quality or real webhook delivery. |

`backend/tests/conftest.py` disables real LLM calls for every test by default. The shared `market` fixture in `test_lifecycle_integration.py` requires `TEST_DATABASE_URL` ending in `_test`, serializes schema recreation with a PostgreSQL advisory lock and overrides the application database. Tests without that variable **skip**; collecting or running only the unit subset is insufficient. Some tests deliberately seed otherwise hard-to-reach rows or call internal workers/services; those are integration fixtures, not a complete user journey.

At the inventory baseline, `workflow.integration.spec.ts` contains four optional Browser/API/DB tests, all skipped unless `TASKMATCH_E2E_API` is set: one legacy manual project lifecycle and one dashboard traversal for each of admin, client and developer. The ordinary browser suite principally uses API fixtures. Enabling these four is a separate result to record, not something inferred from the larger browser pass count.

The final repeat again produced **29 + 62 + 29 + 62**, all four exit codes 0 and zero financial operations; SDK unit source was unchanged, so the earlier 17/16 unit results remain applicable.

These are **182 individual assertions across four smoke invocations**, not 182 independently defined test cases. Every SDK call used its normal transport to the running API backed by isolated PostgreSQL; Redis was provisioned with the stack. Direct setup HTTP is limited to schema/taxonomy and principal/delegation endpoints not wrapped by the SDK. The scripts publish/fund no mission and perform **zero financial operations**. They accept only loopback origins on the two explicitly provisioned ports; `--human` requires paid API port 3172. Both scripts were also executed with the public production URL, unrelated local port 8000 and human mode on legacy port 3171: all six negative runs exited at the local API guard with zero checks/requests.

Testing exposed a real creation blocker: both SDKs sent USD when `create_job` / `createJob` omitted currency, but the API accepts EUR for new jobs. A new regression first failed in each SDK with `USD != EUR`; defaults and README examples were corrected to EUR. Full SDK unit suites then passed, and all four real HTTP smoke runs created and reread EUR drafts without passing a currency argument. Explicit USD still yields typed HTTP 422, preserving the server validation contract.
